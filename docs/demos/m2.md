# M2 demo: isolation and review, "Issue to PR"

Prerequisites: M1 done; `gh auth status` signed in (used for `gh pr create`).

## One-time: a standalone target repo

The Issue-to-PR template needs a repository of its own (worktrees are created inside it and a PR is opened against it). Create a private one from the sample project:

```powershell
pnpm orca sample init ../orca-sample-target --remote <your-github-user>/orca-sample-target
```

This copies `examples/sample-target`, runs `git init` + first commit, `npm install`, then `gh repo create --private --push`. The template's `settings.repoPath` is `../../orca-sample-target` relative to `templates/`, i.e. a sibling of the monorepo.

## In the browser

```powershell
pnpm dev
```

1. Sidebar > Templates > **Issue to PR**, then **Run**. Fill in the task in the inputs dialog (a default is provided) and press Run.
2. `plan` (Copilot, read-only, structured result) runs for ~30 s. The **Approve the plan** card appears at the top: summary, numbered steps, files. Approve.
3. `implement` runs in a fresh git worktree (`<repo>/.orca/worktrees/<run8>-implement`, branch `orca/issue-to-pr/<run8>/implement`, `node_modules` junction-linked). The test/fix loop runs `npx vitest run` inside that worktree until green (max 3). `changes` computes the diff; `review` (judge) returns approve/findings.
4. The **Approve the change** card shows the reviewer verdict, findings, test result, and the colored diff. Click the `implement` node to see its Diff tab with keep/discard buttons. Approve.
5. `commit` -> `push` -> `pr` (draft, via `gh pr create`) -> `done` toast with the PR URL. Reject instead and `discard` removes the worktree and branch, then `rejected` notifies.

## Headless equivalent

```powershell
pnpm orca run issue-to-pr --approve-all --input "task=Fix divide() and average() so the tests pass"
```

`--approve-all` approves both gates and any tool permission; without it gates are rejected.

- Engine tests: worktree isolation end to end (agent writes in worktree, shell in the same worktree, diff shows `+new feature`, commit lands on the branch, gate rejection removes worktree and branch), judge structured results and `approve`/`score` outputs, failure when a judge never calls `submit_result`.

## Known limitations (carried to M3)

- Toasts do not auto-dismiss; browser `Notification` permission is not requested yet.
- `git pr.create` uses `gh`; the GitHub MCP path is not exercised.
- Worktree sweep (retention) is not implemented; kept worktrees stay until discarded from the UI or `git worktree remove`.
- Windows: `git checkout` warns about LF/CRLF in the sample repo; harmless.
