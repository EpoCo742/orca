# M3 demo: scale-out and integrations

Prerequisites: M2 done (standalone sample repo at `../orca-sample-target`).

## Parallel review (Map + judge)

Sidebar > Templates > **Parallel review** > Run (input: paths for `git ls-files`, default `src test`).

- `list` (shell) -> `files` (transform) -> **Map** `review` runs one read-only `reviewer` agent per file, up to 4 at once; each returns `{ file, score, findings }` through `submit_result`.
- `collect` flattens `nodes.review.results`, `merge` (judge) ranks everything, the `report` gate shows verdict, summary, top findings, and per-file scores; `done` notifies.
- The map node shows `n/m items` while running; click `reviewer` in Run mode to switch between item tabs `review[0]`, `review[1]`, ...

Verified 2026-09-10: 2 files reviewed concurrently, verdict "fix first (3/10)", 11 premium requests.

## Tournament (Map with per-item worktrees)

Sidebar > Templates > **Tournament** > Run.

- `variants` yields three prompt styles; **Map** `contest` runs `implement` (isolation: worktree) and `test` (worktreeOf: implement) per item. Each item gets its own worktree, keyed `implement-0`, `implement-1`, `implement-2`.
- `diffs` summarises pass/fail per contestant, `judge` inspects the branches with `git diff` and returns `{ winner, ranking, rationale }`, `has_winner` routes, the `approve` gate shows the rationale, `keep` keeps the winner's worktree, a second map `losers` discards the rest, `done` notifies.

Verified 2026-09-10: all three contestants passed, judge chose "documented", after approval only `.orca/worktrees/<run8>-implement-2` remained (unlocked, kept); losers' worktrees and branches removed. 21 premium requests.

## MCP tool node and secrets

1. Sidebar > Secrets: add `GITHUB_TOKEN` (a PAT; `gh auth token` works for a quick test). Values are AES-256-GCM encrypted in `%APPDATA%\orca\secrets.enc.json` with a generated master key (or `ORCA_MASTER_KEY`).
2. Workflow inspector > MCP servers > Add from preset > **GitHub (remote)** > Test connection (lists the server's tools).
3. Add an **MCP tool** node: server `github`, List tools, pick `list_pull_requests`, args `{ "owner": "...", "repo": "...", "state": "open" }`. Its `result` port carries the parsed JSON.
4. Agent nodes can attach the same servers (checkboxes under Denied tools); allow their tools with `Mcp(github/*)` rules.

Verified 2026-09-10: `list_pull_requests` on `EpoCo742/orca-sample-target` returned PR #1; the token string appeared zero times in the run's persisted events and transcripts (redaction replaces secret values with `***`).

## Also in M3

- Join node (all / any), Sub-workflow node (child run, outputs of top-level nodes), Copilot budget tracker with unit tests, worktree retention sweep at engine start (7 days by default, `settings.retention.worktreesDays`), toasts auto-dismiss.
- Atlassian preset is defined (mcp-remote OAuth bridge) but untested: no Jira site was available.

## Known limitations (carried to M4)

- Failed or cancelled runs leave their worktrees locked until the retention sweep; a "discard all for run" control is missing.
- Model output sometimes carries stray tags (seen once: `</summary>` in a judge summary); no post-processing yet.
- The MCP inspect call connects synchronously and can take 10-20 s for `npx` stdio servers on first use.
